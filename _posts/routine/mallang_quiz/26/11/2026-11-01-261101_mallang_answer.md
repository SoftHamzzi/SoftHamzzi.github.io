## Q4. 🟡 보통 — ⭕ 10/10

**문제:** 다음 명제가 참(O)인지 거짓(X)인지 판단하라.

> 클래스 템플릿 `Widget<T>`에 대해 `swap`을 지원하려고 `std` 네임스페이스 안에 `template<typename T> void swap(Widget<T>& a, Widget<T>& b)`를 오버로딩으로 추가하면, 컴파일도 되고 표준에도 어긋나지 않으므로 안전한 해결 방법이다.

**📝 내 답:** X. std 네임스페이스에 완전 템플릿 특수화는 허용하지만, 템플릿 추가는 불가능하다.

**정답: X**

**해설:**

이 코드는 컴파일은 되지만, `std` 네임스페이스에 새로운 템플릿 함수를 추가하는 것은 표준 위반이라서 실행 결과가 미정의 동작(UB)이다. `std` 안의 기존 템플릿에 대한 완전 특수화는 가능하지만 새 템플릿을 추가할 수는 없다. 올바른 방법은 `Widget`이 들어 있는 사용자 네임스페이스 안에 비멤버 `swap`을 오버로딩으로 제공하는 것이다(인자 기반 탐색(ADL)으로 선택됨).

**🔍 피드백:** 판단(X)과 근거(`std`에는 완전 특수화만 허용되고 새 템플릿 추가는 불가)가 정확합니다. 이 주제는 이전에 약했는데 이번에는 정확히 정리하셨습니다. 한 가지 덧붙이면, 표준 위반의 결과가 미정의 동작이고 올바른 해법은 사용자 네임스페이스의 비멤버 `swap`(+ ADL)입니다.

## Q5. 🟡 보통 — ❌ 0/10

**문제:** 아래 코드에서 `value(std::move(text))`를 실행할 때 실제로 호출되는 `std::string`의 생성자는 무엇인가?

```cpp
class Annotation {
public:
	explicit Annotation(const std::string text)
	: value(std::move(text))
	{ … }

private:
	std::string value;
};
```

- A. 이동 생성자
- B. 복사 생성자
- C. 어느 생성자도 호출되지 않고 컴파일 오류가 난다.
- D. 기본 생성자

**📝 내 선택:** A. move 함수는 통해 string의 이동 생성자를 호출한다.

**정답: B**

**해설:**

`text`가 `const std::string`이므로 `std::move(text)`의 결과는 `const std::string&&`, 즉 const rvalue다. `std::string`의 이동 생성자는 const가 아닌 `std::string&&`를 받아 이 인수를 받을 수 없다. 반면 복사 생성자는 `const std::string&`를 받아 const rvalue도 바인딩할 수 있으므로 결국 복사 생성자가 호출된다(컴파일 오류도 아니다). 이동을 지원할 객체는 `const`로 선언하지 말아야 하며, `std::move`는 실제로 아무것도 이동하지 않고 결과가 rvalue라는 것만 보장한다.

**🔍 피드백:** `std::move`가 이동 생성자를 호출한다고 생각하신 것이 함정에 걸린 부분입니다. 이 문제의 핵심은 매개변수가 **`const std::string`**이라는 점입니다. `std::move`는 아무것도 이동시키지 않고 rvalue로 캐스팅할 뿐이며, 결과 타입이 `const std::string&&`이라서 `std::string&&`를 받는 이동 생성자는 쓸 수 없고, `const std::string&`를 받는 복사 생성자가 호출됩니다. 이동을 지원하려면 `const`를 붙이지 마세요.

## Q6. 🔴 어려움 · 📌 오답노트 — ⭕ 10/10

**문제:** C++의 `const`에 대해 답하시오.

(1) 아래 세 포인터 선언에서 각각 포인터 자체를 수정할 수 있는지, 가리키는 데이터를 수정할 수 있는지 쓰시오.

```cpp
char greeting[] = "Hello";
const char *       p1 = greeting;
char * const       p2 = greeting;
const char * const p3 = greeting;
```

(2) 아래 코드에서 `const vector<int>::iterator it`와 `vector<int>::const_iterator cit`는 각각 `*it = 10;`, `++it;`, `*cit = 10;`, `++cit;` 중 무엇이 가능하고 무엇이 불가능한가?

```cpp
vector<int> vec;
const vector<int>::iterator it = vec.begin();
vector<int>::const_iterator cit = vec.begin();
```

(3) 아래 코드는 `operator[]`가 `const` 멤버 함수이므로 컴파일은 되지만, 상수 객체 `cctb`의 내용이 바뀐다. 이런 일이 벌어지는 이유를 "비트수준(물리적) 상수성"의 정의와 연결해 설명하고, 이를 보완하기 위해 나온 개념(논리적 상수성)의 정의를 쓰시오.

```cpp
class CTextBlock {
public:
	char& operator[](size_t position) const { return pText[position]; }
private:
	char* pText;
};

const CTextBlock cctb("Hello");
char* pc = &cctb[0];
*pc = 'J';
```

(4) 아래 `length()`는 값을 캐시해 두려고 `const` 멤버 함수 안에서 멤버를 수정하다가 에러가 난다. 에러가 나는 이유와 해결 방법(키워드와 그것을 붙일 대상)을 쓰시오.

```cpp
class CTextBlock {
public:
	size_t length() const;
private:
	char* pText;
	size_t textLength;
	bool lengthIsValid;
};

size_t CTextBlock::length() const {
	if(!lengthIsValid) {
		textLength = strlen(pText);
		lengthIsValid = true;
	}
	return textLength;
}
```

**📝 내 풀이:**

(1) const char * 는 포인터 O, 데이터 X
char * const 는 포인터 X, 데이터 O
const char * const는 포인터 X, 데이터 X

(2) *it=10 O, ++it X, *cit=10 X, ++cit O

(3) 비트수준 상수성은 어떤 비정적 데이터 멤버라도 수정이 되지 않아야 const라는 규칙이다.
하지만 내부에서 지켜진다 하더라도, 내부 참조값을 반환해버리는 경우 이러한 규칙이 깨진다.
이를 위해 나온것이 논리적 상수성으로, 외부에서 알아차리지 못하게 내부 상태를 수정하면 괜찮다는 규칙이다.

(4) textLength와 lengthIsValid의 값을 변경하고 있기 때문이며, 이들 자료형 앞에 mutable을 붙여주면 된다.

**정답:**

(1) `p1`(`const char *`): 포인터 수정 O, 데이터 수정 X. `p2`(`char * const`): 포인터 수정 X, 데이터 수정 O. `p3`(`const char * const`): 포인터 수정 X, 데이터 수정 X. (`const`가 `*`의 왼쪽에 있으면 데이터가 상수, 오른쪽에 있으면 포인터가 상수다.)

(2) `const vector<int>::iterator it`는 `T * const`처럼 동작한다: `*it = 10;` 가능(데이터 수정 O), `++it;` 불가능(포인터/주소 수정 X). `vector<int>::const_iterator cit`는 `const T *`처럼 동작한다: `*cit = 10;` 불가능(데이터 수정 X), `++cit;` 가능(주소 수정 O).

(3) 비트수준 상수성은 멤버 함수가 객체의 어떤 데이터 멤버도 건드리지 않아야 `const`로 인정하는 것이다. 이 함수는 `pText` 멤버 자체를 수정하지 않으므로 비트수준 상수성을 만족해 컴파일되지만, 반환값이 가리키는 주소를 통해 외부에서 값을 수정할 수 있다. 이를 보완하기 위한 논리적 상수성은 일부 몇 비트 정도는 수정할 수 있되, 그것을 사용자 측에서 알아채지 못하면 된다는 개념이다.

(4) `const` 멤버 함수 안에서는 비트수준 상수성에 따라 멤버 변수를 수정할 수 없기 때문에 `textLength`와 `lengthIsValid`에 대입하는 부분에서 에러가 난다. 해결은 이 두 변수의 선언 앞에 `mutable` 키워드를 붙여 `const`의 제한에서 예외 대우를 받게 하는 것이다(`mutable size_t textLength; mutable bool lengthIsValid;`).

**🔍 피드백:**

- (1) 2.5/2.5 — 세 선언의 포인터/데이터 수정 가능 여부를 모두 정확히 답했습니다.
- (2) 2.5/2.5 — `it`는 `*it` 수정 가능·`++it` 불가, `cit`는 `*cit` 수정 불가·`++cit` 가능으로 정확합니다.
- (3) 2.5/2.5 — 비트수준 상수성의 정의, 내부 참조를 반환하면 규칙이 깨진다는 이유, 논리적 상수성의 정의를 모두 맞게 설명했습니다.
- (4) 2.5/2.5 — 에러 이유와 해결(`textLength`, `lengthIsValid` 선언 앞에 `mutable`)이 정확합니다.

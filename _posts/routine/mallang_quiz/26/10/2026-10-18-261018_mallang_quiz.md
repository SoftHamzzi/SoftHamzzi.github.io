C++에서 객체를 람다의 클로저 안으로 이동하는 방법에 대한 설명이다.

- `std::unique_ptr`처럼 이동 전용인 객체를 클로저 안으로 이동하려면 C++14에서 도입된 ① `___`를 사용한다. (한글 용어 두 단어, '일반화된 람다 캡처'라고도 한다)
- `[pw = std::move(pw)]`에서 `=`의 좌변은 람다로부터 생성되는 클로저 클래스에 속한 ② `___`의 이름이고, 우변은 그것을 초기화하는 표현식이다. (두 단어)
- C++11에서는 이동 캡처를 직접 지원하지 않으므로, 객체를 ③ `___`가 생성하는 함수 객체(바인드 객체) 안으로 이동 생성한 뒤 그 객체에 대한 참조를 람다에 넘겨주는 방식으로 흉내 낸다. (함수 이름, `std::` 제외)
- 위 방식에서 람다 안에서 이동된 객체를 수정하려면, 람다를 ④ `___`(으)로 선언하고 매개변수 선언에서 `const`를 제거해야 한다. (C++ 키워드)

## Q6. 🔴 어려움 · 📌 오답노트 (2번째 복습)

C++ private 상속과 공백 클래스에 대해 답하시오.

```cpp
class Empty {};

class HoldsAnInt {
private:
   int x;
   Empty e;
};
```

(1) 위 코드에서 `sizeof(HoldsAnInt)`가 `sizeof(int)`보다 커지는 이유를 쓰시오.

(2) `HoldsAnInt`가 `Empty`를 `private`으로 상속하도록 바꾸면 `sizeof(HoldsAnInt)`가 어떻게 되는가? 이 최적화의 이름과, 이 최적화가 적용되는 조건(상속의 형태)을 쓰시오.

(3) `class Student : private Person { ... };`일 때, `void eat(const Person& p);`에 `Student` 객체를 넘기면 컴파일되지 않는다. 그 이유와, private 상속이 의미하는 관계를 쓰시오. 기본 클래스에서 물려받은 멤버는 파생 클래스에서 어떤 접근 수준이 되는가?

(4) 객체 합성을 쓸 수 있다면 합성을 쓰는 것이 원칙이다. 그럼에도 private 상속을 써야 하는 경우 세 가지를 쓰시오.

> **출처:** `game_dev/cpp/chapter6/2025-10-26-cpp_6_39.md`
> **오답노트:** `wn-61908b44` · 2026-09-16 최초 오답 · 이번이 2번째 복습

**📝 내 풀이:** (1) 공백 클래스를 멤버로 가지려면 1바이트라도 채워야하기 때문이다. 그렇기에 커진다.

(2) 공백 클래스가 크기를 가지지 않는다. EBO이며, private여야 하고 멤버로 가지면 안되며, 공백 클래스이어야한다.

(3) private 상속을 하게 되면, 암시적 변환을 허용하지 않는다. private 상속은 is-implemented-means-of이다.  
물려받은 멤버는 파생 클래스에서 private 접근 수준이 된다.

(4) 함수 중 일부만 재정의하여야 하는 경우, EBO를 사용해야하는 경우, 나머지 하나는 모르겠다.

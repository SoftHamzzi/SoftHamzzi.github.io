## Q1. 🟢 쉬움

빈칸을 채우시오.

패키지 게임에 게임 서버가 들어오기까지는 네 단계를 거쳤다.

```
1. 단독 플레이      네트워크 없이 로컬에서만 플레이
        ↓
2. ① ___ 플레이     두 플레이어 간 직접 연결
        ↓
3. ② ___ 방식       플레이어 세 명 이상이 인터넷으로 함께 플레이하되,
                    그중 한 명이 ③ ___ 역할을 겸해 게임 상태를 관리하고 동기화한다
        ↓
4. ④ ___ 서버       렌더링과 사용자 입력 처리를 하지 않고,
                    순전히 클라이언트의 연결만 처리하는 전용 프로그램
```

3번 방식에는 약점이 있다. 서버 역할을 맡은 플레이어도 게임에 참여하고 있으므로 그쪽이 유리해질 수 있어 ⑤ `___` 문제가 생기고, 그 플레이어가 게임을 나가 버리면 게임 전체가 흔들린다.

4번은 그 두 약점을 모두 없앤다. 게임 플레이에 참여하지 않고 오직 서버 기능만 수행하기 때문에, 특정 플레이어의 네트워크나 성능에 영향을 받지 않고 24시간 안정적인 서비스가 가능하다.

```
[클라이언트] ──▶ [인증 서버 ×4] ──▶ [유저 DB]   ← 여기가 병목
```

(3) (2)를 완화하는 첫 번째 방법이 **일관된 해시 알고리즘**이다. 아래 그림을 보고 답하시오.

## Q3. 🔴 어려움

온라인 게임에서 다른 플레이어의 캐릭터를 화면에 그리는 문제다.

서버가 보내 준 위치 정보는 네트워크를 타고 오느라 **이미 한 템포 늦은 값**이다. 그래서 지나간 시간만큼 위치를 예측해서 그린다. 이것을 **추측 항법**이라 한다.

```
송신자 측 위치: P0      수신자 측 위치: P      레이턴시: a

t=0 시점 : P(t=0+a) = P0(t=0) + a * V0(t=0)      ← 속도로 앞질러 예측
t=1 시점 : P(t=1+a) = P0(t=1) + a * V0(t=1)      ← 새 원본이 도착해 다시 예측
```

레이턴시 `a`는 아래처럼 측정한다.

```
① 기기 A가 기기 B에 패킷을 보낸다
② 기기 B는 받자마자 기기 A에게 패킷을 되돌려 보낸다
③ 기기 A는 (현재 시간 − 보낸 시간)을 잰다
```

이 상황에 대한 설명으로 **가장 올바른 것**은?

- A. ③에서 잰 값이 곧 레이턴시 `a`이므로 그대로 예측식에 넣으면 된다. 이 왕복 측정값을 RTT라 부르며, 편도 시간을 따로 구할 필요는 없다.
- B. `t=0`에서 하던 예측과 `t=1`에서 새로 시작한 예측은 **어차피 예측이므로 값이 일치할 수 없다.** 그래서 실제로 렌더링하는 위치 `P_follow`를 새 목표 `P_target`으로 순간 이동시키지 않고 **선형 보간하며 따라가게** 만든다. 이렇게 레이턴시가 만드는 문제를 감추는 기법들을 통틀어 **레이턴시 마스킹**이라 한다.
- C. 추측 항법을 도입하면 위치가 정확히 예측되므로, 전송 텀이 길어서 생기는 끊김을 메우는 **상태 값 보정(선형 보간·스플라인)은 더 이상 필요 없다.** 둘은 같은 문제를 푸는 방법이라 하나만 쓰면 된다.
- D. 서버가 게임 로직·렌더링·화면 송출을 모두 맡고 클라이언트는 입력과 화면 출력만 하는 방식이 있다. 클라이언트가 그래픽 리소스를 갖지 않아 보안이 완벽하고, 클라이언트가 할 일이 적어 레이턴시도 가장 낮다. 그래서 현대 온라인 게임은 이 방식으로 돌아가는 추세다.

> **출처:** `server/game_server/5/2026-02-13-game_server_5_2.md`

**📝 내 선택:** B.

틀린 이유:  
- A: ③에서 잰 값은 RTT이며, a는 RTT/2로 구해야 한다.
- C: 위치가 정확히 예측되지 않아서 쓰는 것이, 레이턴시 마스킹이다.
- D: 마지막 문단이 틀렸다. 현대 온라인 게임은 서버 부하가 커지기에, 클라/서버가 나눠 처리한다.

멀티스레딩에서 공유 데이터를 다룰 때의 문제다.

```cpp
x = t
```

(1) `x = 2`인 상태에서 **스레드 1이 `x += 3`을, 스레드 2가 `x += 4`를** 동시에 실행한다. 순서대로 잘 실행되면 `x = 9`가 되어야 한다. 그런데 실제로는 `x = 5`가 나올 수 있다.

- ㉠ 위 세 줄을 이용해 **`x = 5`가 되는 실행 순서**를 단계별로 적으시오. (어느 스레드가 어느 줄을 언제 실행하는지)
- ㉡ 이 현상을 무엇이라 부르는가?

(2) 아래는 스레드 4개로 100만까지의 소수를 구하는 코드다. 겉보기엔 멀쩡하지만 **치명적인 문제가 두 가지** 숨어 있다. 각각 어떤 변수에서 무슨 일이 벌어지는지 설명하시오.

```cpp
int num = 1;
Array<int> primes;      // 내부에 [배열 포인터]와 [크기 정보]를 멤버로 가진다

ThreadProc() {
    while (num <= 1000000) {
        if (IsPrime(num))
            primes.Add(num);
        num++;
    }
}

main() {
    Array<Thread> threads;
    for (int i = 0; i < 4; i++)
        threads.Add(BeginThread(ThreadProc));
```

## Q5. 🟡 보통

다음 명제가 참(O)인지 거짓(X)인지 판단하라.

> OSI **2계층인 데이터 링크 계층**은 LAN 안에서의 통신을 담당한다. 단말기마다 고유한 **MAC 주소**가 있고, 데이터는 **프레임** 단위로 오간다. 프레임은 송신자와 수신자 주소를 담은 **헤더**와 실제 데이터인 **페이로드**로 이루어진다.
>
> **3계층인 네트워크 계층**은 여러 LAN 사이의 경로를 설정하고 데이터를 전달한다. 라우팅·포워딩·세그멘테이션·인터네트워킹이 주요 기능이며, **라우터**와 일부 L3 스위치가 이 계층에서 동작한다.
>
> 그런데 스위치 하나에 연결할 수 있는 단말기 수에 한계가 있는 것은, 결국 **MAC 주소가 32비트뿐이라 주소 공간이 모자라기 때문**이다. 그래서 128비트 주소를 쓰는 **IPv6로 넘어가면 이 한계가 사라져** LAN 하나에 사실상 무제한으로 단말기를 붙일 수 있게 된다.

> **출처:** `server/game_server/2/2025-06-30-game_server_2_1.md`

**📝 내 답:** X. 마지막 단락이 틀렸다. 이는 MAC 주소가 아닌 IP 주소에 대한 내용이다.
